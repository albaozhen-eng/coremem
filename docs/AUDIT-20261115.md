## 二、缺陷（按严重度）

### P0-1　L1 断供 2 天：本地模型被内存守卫拒绝

**现象**：笔记停在 `2026-11-13.md`，`unified-facts` 最后写入 11-13 15:07，
`capture_state.last_run` 停在 11-14T23:37。11-14 有 8 个会话活动 → **不是没输入**。

**根因**（实测）：
```
本地 Qwen3.8-Flash-Next-oQ4e-mtp → HTTP 400
oMLX prefill memory guard rejected: Prefill would require ~122.66 GB peak
(current 73.15 + KV+SDPA 49.51) but dynamic ceiling is 98.95 GB
```
该模型 `max_context_window=131072`（128K），KV cache 撑爆守卫。
同机 `Qwen3-8B-mlx-4bit` 返回 **200**，Flash 返回 **400**。

**为什么"手动能通、定时失败"**：手动跑时百炼兜底可用（实测 7s 出 15 条）；
定时轮次落在云端限流/额度窗口时，本地 400 + 云端失败 = 全链断，
`capture` 按 fail-fast 停止本轮。**单点从"本地"变成了"云端"，韧性反而下降。**

**验证**：`curl -s -X POST http://127.0.0.1:9999/v1/chat/completions -d '{"model":"Qwen3.8-Flash-Next-oQ4e-mtp",...}'`

### P0-2　BOSS 数据曾脱离备份（我引入，已修并验证）

11-12 迁移把 BOSS 数据搬到 `~/.boss-agent`，但 `tiered-backup.sh` 源清单没跟着改：
检查点里 `.boss-agent/` **0 条**，体积 3.2G → **193M**。

已补 `.boss-agent` 到三处源清单，实跑后 **864M / 10117 条目 / .boss-agent 3602 条**，
`send-queue.json`、`decision-registry.json`、`send-policy.json` 均在。

**这是本次审计最严重的问题，且是我自己造成的。** 教训：迁移数据必须同步检查备份源清单，
"任务 rc=0" 不代表备份内容正确。

### P1-1　三个绿探针是"过去时"，抓不到停产

| 探针 | 数据源 | 盲区 |

### P1-2　退役闸门有 3 个假绿漏洞（实测）

## 三、完善方案（按优先级，每项写清怎么验证）

### P0-A　恢复本地通道（消除单点）

三步，按顺序做，每步独立验证：

1. **降 Flash 的 context**：`~/.omlx/model_settings.json` 里
   `Qwen3.8-Flash-Next-oQ4e-mtp.max_context_window` 131072 → **32768**。
   capture 实际只送 ~6000 字（≈3000 token），32K 足够。
   *验证*：`curl` 该模型返回 200；`memory_capture.py --dry-run` 日志无 HTTP 400。
   *风险*：BOSS 也用该模型，需确认它的最长 prompt < 32K（先量再改）。

2. **加小模型兜底通道**：在 `_build_llm_channels` 的本地档位后插入
   `Qwen3-8B-mlx-4bit`（实测 200）。顺序：Flash → 8B → 百炼。
   *验证*：临时把 Flash 模型名改错，跑 capture 应看到"切到 8B 成功"而非直接跳云端。

3. **fail-fast 改为有界重试**：现在单轮全链失败即停。改为连续失败 ≥3 轮才停，
   并在状态里记 `consecutive_fail`。
   *验证*：注入 3 次失败，断言前 2 轮仍继续、第 3 轮停且状态可见。

### P0-B　补一次真实恢复演练（已做，纳入常规）

本次演练（**不碰生产**）：
```bash
T=/tmp/restore-drill && mkdir -p $T
F=$(ls -t ~/.coremem/backups/tiered/checkpoints/*.tar.gz | head -1)
tar -xzf "$F" -C "$T" .coremem/MEMORY.md .coremem/memory/2026-11-13.md
diff "$T/.coremem/MEMORY.md" ~/.coremem/MEMORY.md   # 实测：逐字节一致
```
**纳入月更**：每月抽 3 个文件解到临时目录比对，失败即告警。
*验证*：任务产出 `health/restore-drill.json`，含比对结果与抽样文件名。

### P1-A　给"过去时"探针加新鲜度判据

- `l2_recall`：报告 >8 天已判黄，但**当前 11-12 的报告在 11-15 仍报绿**——
  查明为何未触发（可能是 mtime 与 `generated_at` 口径不一致），修到真能判黄。
  *验证*：把报告 mtime 改成 10 天前，探针必须变黄。
- 新增 `pipeline_throughput` 探针：近 24h 新增事实数；为 0 且同期有会话活动 → 红。
  *验证*：构造"有会话无新事实"的状态，探针必须红；无会话时必须绿（不重演"把空闲当故障"）。

### P1-B　补闸门 3 个漏洞

1. 扫描范围加 `~/.agents/skills-openclaw`、`~/projects`（或改为全机有界扫描）。
   *验证*：现在跑闸门必须报出那 38 个文件，而不是 0。
2. `tiered-backup.sh` 第 236 行 `cd ~/.openclaw/workspace` 改为条件执行：
   目录不存在则跳过 git 快照并记日志，不再无条件 cd。
   *验证*：临时改名旧根，跑 backup 应 rc=0 且日志有"跳过"，而非报错。
3. 写入窗口从 3 天改为**自迁移完成时刻起**（marker 文件），并把周/月更任务纳入。
   *验证*：闸门报告里列出每个低频任务的最后运行时间。

### P2-A　建立能测改进的基准

现有 KIS 已饱和。新增 **难题集**：从 L1 里挑"答案不在查询词面"的题（跨日推理、
指代、需要合并两条事实），目标 n≥150（CI 约 ±5 点）。
*验证*：新集在现役系统上的分数应显著低于 99.7%（否则说明还是太容易），
且同一改动在旧集不变、新集有可测变化。

### P2-B　把"独立复核"变成可执行的前提

本次复核因余额不足失败。改进：复核前先跑一次**极小 prompt 探活 + 余额检查**，
不足则自动降级到更便宜的模型或明确报告"未做独立复核"，**不要静默跳过**。
*验证*：模拟余额不足，流程应输出"独立复核未完成 + 原因"，而不是产出一份看似完整的报告。

## 四、不建议做的

- **不要用 KIS/golden 验证优化**：分辨率不够，会把噪声当成果。
- **不要为了闸门变绿而放宽判据**：本次 3 个漏洞正是"白名单/窗口"放宽导致的。
