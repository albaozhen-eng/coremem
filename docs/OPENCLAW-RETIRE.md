# 为什么 OpenClaw 退役做过两次都没成功

复盘时间：2026-11-13　依据：L1 每日笔记（`~/.coremem/memory/*.md`）原始记录

## 两次"宣布完成"

| 时间 | 当时的说法 | 实际覆盖范围 |
|---|---|---|
| **2026-10-30** | 「coremem 已实现真正独立于 OpenClaw，语义图、配置、日记、会话及脚本均已迁移」 | 数据根 + L1/L2 + 脚本；**launchd 只改了 1 个**（`ai.boss.memory-buffer-flush`）|
| **2026-11-03** | 「完成 OpenClaw 解耦重构，21 个部署文件与仓库逐字一致，心跳检查问题数为 0」 | 代码层解耦：capture 默认只读 pi、新增 `omlx_runtime.py` / `notify.py` |

10-30 当天还留了一句：
> 「用户计划先使用新架构一两周，确认无误后再删除 OpenClaw 剩余数据及旧 Chroma」

## 四个失败原因

### ① 把"记忆系统解耦"当成了"OpenClaw 可删除"

两次都只处理记忆系统。但 `~/.openclaw` 里还住着：

- **BOSS 招聘系统**：108 个 `boss-*.py`，94 个含旧根硬编码（158 处）
- **25 个独立项目**：12.6GB，其中 **13/14 子项目没有 git**，`quartz-buddhist-site` 还有 344 处未提交

记忆系统独立 ≠ 那个目录能删。**范围误判。**

### ② 验证只覆盖自己改的部分

11-03 的证据是「21 个部署文件逐字一致 + 心跳问题数 0」。
这两项**都只测记忆系统**，没有一条检查是「全机还剩多少 plist 指向旧根」。

2026-11-12 一查：**51 个**。

> 这与本项目反复出现的失败模式同源：**测的是自己改动的东西，不是目标本身。**

### ③ launchd 只改 1 个就宣布完成

10-30 记录明确写着只改了 `ai.boss.memory-buffer-flush`。
其余几十个任务仍指旧根 —— 删目录就会静默失效。

### ④ "观察一两周"没有落成任何可检查的东西

那句话没有到期提醒、没有删除前置清单。
证据：10-31、11-01、11-09 的 L1 记录里 `coremem` 提及数为 **0** —— 话题自然沉掉了。

## 这次改了什么

判据从"我觉得改完了"换成**可穷举、可复查**的量：

| 之前 | 现在 |
|---|---|
| 「21 个文件一致」 | `openclaw-retire-gate.sh`：全机 plist 旧根引用 = 0 |
| 「心跳问题数 0」 | 46 个任务逐个 kickstart，**看产物 mtime 推进**而非只看 rc |
| 只搬记忆系统 | 先查清 26G 里每一项归谁；无 git 的项目先搬不删 |
| 「一周后删」 | `openclaw-retire-watch.sh`：每日 09:15 复查，到期自动通知 |

## 闸门查出的、前两次都没发现的问题

1. **改 plist 不等于生效**：`kickstart -k` 用的是**已加载的旧任务定义**，不重读文件。
   必须 `bootout` + `bootstrap`。`llm-failover` 因此在迁移后仍跑旧脚本、持旧根句柄。
   → 本次强制重载 48 个任务后句柄才清零。

2. **路径套叠**：`sender-health` 的日志路径被替换成
   `.boss-agent/workspace/boss-agent/data/...`（多了一层），任务静默失败。

3. **常驻进程不受 plist 更新影响**：迁移前启动的进程会一直持有旧路径句柄，
   必须重启。这是"文件都改对了但系统还在用旧路径"的典型。

4. **闸门自身要引用旧根**：它和 watch 脚本以旧根为检查目标，
   一开始把自己报成阻塞项 —— 已加白名单。

## 仍未闭环的部分（截至 2026-11-13）

闸门当前仍报阻塞，这是**它在正常工作**，不是误报：

- 旧根仍有少量写入（`memory_index.log` / `boss-config-mirror.log` /
  `contrib-report` / `boss-sheet-times.log`）。已确认相关脚本内**无旧根硬编码**，
  写入来自进程继承的工作目录或白名单内的 `tiered-backup`（它有意 `cd ~/.openclaw/workspace` 做 git 快照）。
  需要再观察一个调度周期确认是否自然停止。
- `com.lealway.plugmem-tunnel` rc=255 —— 迁移前即失败（隧道问题），已列入已知白名单候选。
- BOSS 多个任务 rc≠0 的真因是 **`LOGIN_WALL`：BOSS 网页会话失效需人工登录**。
  最早出现 **09-10**，比迁移早两个月，与迁移无关。

## 到期时怎么做

观察期到 **2026-11-19**，届时 `com.coremem.openclaw-retire-watch` 会自动通知。

```bash
# 手动复查
bash ~/.coremem/scripts/openclaw-retire-gate.sh

# 全绿后，先重命名观察一天（可回退），不要直接销毁
mv ~/.openclaw ~/.openclaw.retired
```

**关键**：到期动作是「跑一遍闸门」，不是「靠谁记得」。这是前两次缺的那一环。
